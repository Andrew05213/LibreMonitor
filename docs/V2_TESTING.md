# v0.2 验收清单（计划，非实测结果）

## 界面
- 首页只显示指标名称、数值和单位；删除宣传语、逐项来源说明与卡片底部小字。
- CPU 占用、CPU 温度、逐核频率/负载直接可见；电池电压、电流、功率、温度、健康状态、容量健康度、设计/满充容量、循环处于同级布局。
- 点指标打开来源与缺失原因详情。缺失为“—”，真实 0 保留；不把电池温度、刷新率或应用自身 CPU 冒充其他指标。
- 普通字号、窄屏、大字体、深浅色和读屏仍需真机检查。

## 数据与授权
- 新装/升级不能自动申请 Root；只有前台明确点击才请求。拒绝/超时后不后台重试，关闭使迟到结果失效。
- Root 读数必须实际授权、逐节点成功；开发环境的 proot UID0 不能证明 Android 应用已获权。
- 全局/逐核 CPU 使用同一份计数，切换来源、单项计数回退及热插拔后先建立基线。
- CPU 温度仅接受明确 CPU 来源，不能全热区取最大；未知类型和无效/过期数据均不当成当前值。
- 健康故障状态“良好”不是健康度100%；剩余电荷不是满充容量。容量比只使用同一电池对象、同一单位和同一维度，未知双电芯不自动翻倍。
- 不改变历史库版本、已有记录和七列 CSV；覆盖升级应保持包名与签名、递增应用 versionCode。

## 构建与交付
- JVM 回归、debug 编译、Lint、签名、权限与 APK ZIP 完整性统一由 lead 验证。
- 在结果生成前，不声称新增测试通过或 Root/传感器在本机实显。
- 安装、Root 管理器授权及持续记录/悬浮窗测试均需用户主动操作；不自动安装、不改系统设置。
